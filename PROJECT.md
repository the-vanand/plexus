# Plexus — состояние проекта

Документ описывает, что построено, как оно проверяется и что делать дальше.
Все числа получены прогоном стендов из `tools/harness/`, а не на глаз.
Подробности каждой версии — в [CHANGELOG.md](CHANGELOG.md).

**Версия 0.12.0** · 133 коммита · 104 снимка живых сайтов в фикстурах

---

## 1. Что это

Десктопная визуальная full-stack IDE на Tauri 2: холст с auto-layout моделью
(в духе Figma), генерация чистого HTML/CSS, файловый менеджер, инспектор
свойств, встроенная консоль. Отличительная функция — **импорт чужого сайта по
ссылке**: страница открывается в настоящем браузере, с неё снимается
геометрия каждого элемента, и результат превращается в редактируемую страницу
на холсте.

Ключевой принцип работы над проектом, выдержанный во всех версиях: **искать
корневую причину в движке, а не латать симптом; проверять гипотезу на данных,
прежде чем править; честно называть ограничения.**

## 2. Как устроено

| Слой | Строк | Что делает |
|---|---|---|
| `src/core` | 15 176 | модель документа, решатель раскладки, импорт, кодоген — **без Pixi и React** |
| `src/canvas` | 2 354 | отрисовка на PixiJS, мышь, выделение |
| `src/components` | 3 462 | панели интерфейса на React |
| `src/tauri` | 298 | мост к нативной части |
| `src-tauri/src` | 540 | Rust: окно снимка, файловые диалоги, ACL |
| `tools/harness` | 3 532 | 27 стендов проверки |
| `tools/ci` | 257 | арбитр сборки и эталон метрик |

Главный архитектурный инвариант: **`src/core` не импортирует ни PixiJS, ни
React.** Из-за него рендерер заменяем, а всю логику можно проверять стендами
под Node — на этом и держится вся система проверок.

Крупнейшие модули ядра: `importSnapshot.ts` (3691), `codegen.ts` (1636),
`store.ts` (1406), `pageTemplates.ts` (1310), `importer.ts` (1039),
`scene.ts` (851), `layout.ts` (807).

### Два пути импорта

**Разбор HTML** (`importer.ts` + `css/`) — свой движок каскада: специфичность,
порядок, `clamp()`, `vw`, медиазапросы. Быстро, работает без сети, но на SPA
бессилен: у `music.yandex.ru` в серверном HTML 23 тега и 46 знаков текста.

**Снимок живой страницы** (`snapshot.ts` + `importSnapshot.ts`) — страница
открывается в скрытом окне webview, с каждого элемента снимаются
`getBoundingClientRect()` и `getComputedStyle()`. Своего CSS-движка тут не
нужно вовсе: браузер уже всё посчитал. Основной путь.

## 3. Что сделано

### v0.9.0 — переписан движок импорта HTML

Четыре симптома («размер страницы игнорируется, текст съезжает, теряются
стили и фотографии») оказались следствием пяти системных дыр, три из которых
не чинились правкой импортёра — их не было в модели документа: каскад работал
по принципу «первое побеждает», ширины страницы не существовало, шрифта не
было в модели, `grid` схлопывался в один ряд.

### v0.10.0 — каталог типов

28 блоков в 5 категориях, 7 пресетов раскладки, 6 пресетов контейнера, 7 новых
типов узлов. Блок — это рецепт поддерева из обычных узлов, а не ветка `switch`
в рендерере: новый тип не трогает ни решатель, ни кодоген.

### v0.11.0 — импорт по снимку живой страницы

Второй путь импорта. Точность на COSPEX: dx 172px → 69px → **7px** по мере
устранения двух причин одного класса («применялось только к контейнерам»).

### v0.12.0 — импорт доведён до 4.8 из 5 по внешней оценке

Работа шла циклом **«правка — независимая оценка»**: агент-исправитель менял
код, затем **свежий** оценщик, не знающий истории попыток, снимал живые сайты,
которых исправитель не видел, и выставлял балл по шкале, зафиксированной
заранее. Шесть кругов: **2.7 → 4.6 → 4.3 → 4.2 → 4.7 → 4.8**.

Просадка на третьем и четвёртом круге — не регресс кода, а более жёсткие
наборы сайтов. Именно поэтому шкала требует мерить на невиданном материале:
подгонка под известные снимки иначе неотличима от исправления.

Итог на одиннадцати невиданных сайтах: смещение по X 5.5px, ширины 0px на
девяти сайтах из десяти, ошибка высоты 0.9%, доля узлов точнее 4px — 92.5%.

### После 0.12.0 — правки по наблюдениям пользователя

| Дефект | Как нашёлся | Итог |
|---|---|---|
| снимок не снимался в приложении | первый запуск | три слоя ACL: окно вне capability, нет `remote.urls`, команд не было в манифесте |
| `E0758` при сборке Rust | компилятор пользователя | блочные комментарии в Rust **вложенные**, `http://*` открывал вложенный комментарий |
| `process is not defined` | запуск приложения | забытый отладочный переключатель в браузерном коде |
| снимок делался слишком рано | глаз пользователя | ожидание переписано на тишину в DOM плюс проход прокруткой |
| текст накрыт карточкой | скриншот | не моделировалось обтекание: строки абзаца укорачиваются флоатом |
| слипшиеся слова, нет многоточия | скриншот | **три** носителя одного симптома: сборщик, разбор и каскад в кодогене |
| нет выделения рамкой | запрос | рамка на холсте, Shift добавляет, Alt исключает |

## 4. Как проверяется качество

Это главное, что отличает проект от «просто кода», и это стоит понимать
прежде всего.

### Арбитр сборки

`npm run check` — десять проверок, одинаковых локально и в CI. Решение «можно
мержить» принимает машина по числам: ревью тысяч строк глазами не
масштабируется.

```
✓ tsc --noEmit            ✓ vite build
✓ браузерный код чист     ✓ rust: комментарии
✓ catalog 0 из 28         ✓ templates 0 из 7
✓ breakpoints 0 из 48     ✓ determinism 0 из 8
✓ roundtrip 10 метрик     ✓ snapshot-check 9 метрик
```

Пороги лежат **в репозитории** (`tools/ci/baseline.json`), а не в коде стенда:
порог внутри стенда незаметно стареет вместе с кодом, а эталон в файле
меняется правкой, видимой в диффе. Допуски направленные — улучшение проходит
всегда, ухудшение сверх допуска валит сборку.

Две последние проверки появились потому, что пользователь запустил
приложение: они закрывают классы ошибок, которые песочница не видит в
принципе (синтаксис Rust, Node-глобалы в браузерном коде).

### Шкала оценки импорта

`tools/ci/rubric-import.md` — восемь критериев с весами и числовыми порогами,
зафиксированные **до** начала правок. Оценка строится на сайтах, которых не
было ни у автора правок, ни в фикстурах.

Критерий К7 «редактируемость» существует потому, что идеальная геометрия
достигается тривиально: расставить всё абсолютно по измеренным координатам.
Это даёт точную, но **мёртвую** копию — а редактор ради этого и делается.

### Инструменты

| Стенд | Что меряет |
|---|---|
| `live-snapshot.mjs` | снимает живой сайт настоящим Chromium **тем же текстом сборщика**, что уходит в приложение |
| `snapshot-check.ts` | поэлементная сверка с измеренной геометрией |
| `bulk.ts` | сводка по всем 104 фикстурам разом |
| `overlap.ts` | наложения узлов друг на друга |
| `glue.ts` | слипшиеся куски одной строки |
| `ellipsis.ts` | усечение многоточием |
| `determinism.ts` | один исходник → один документ |
| `truth.ts` | сверка прибора с трассой импорта |

### Три случая, когда врал сам прибор

Стоит записать отдельно, потому что это повторится:

1. **Сопоставление узлов очередью FIFO** ошибалось на 27–29% пар. Прибор
   занижал точность на целый балл: dx 11 против истинных 1.
2. **Детектор слипшихся слов** давал ноль при явной склейке на скриншоте —
   и так трижды подряд, три разные неверные реализации.
3. **Детектор наложений** сверял только текстовые узлы и показывал ноль там,
   где наезжали контейнеры. Слепое пятно прибора — худший род слепоты:
   выглядит как хорошая новость.

Отклонена и одна «починка» прибора: калибровка измерителя текста поднимала
медиану ошибки высоты с 5.4% до 15.4% на невиданных сайтах — то есть была
подгонкой под известные фикстуры.

## 6. Что дальше

По убыванию отношения «польза к затратам».

### Ближайшее

1. **Наложения контейнеров.** YouTube даёт 20 — это то, что пользователь
   видит как «лишние ползунки»: серые пилюли наезжают на кнопки. Данные есть,
   снимок в фикстурах, дефект воспроизводим.

2. **MDN: 5159 наложений.** Корень найден и **отличается** от обтекания:
   Chrome отдаёт свёрнутому `<details>` застывшую геометрию раскрытого
   состояния, соседние списки перекрываются уже в самом снимке. Две попытки
   починки отвергнуты по данным (одна не изменила ничего, вторая ухудшила
   втрое). Глубинная причина — измеритель текста не ломает строку по дефисам,
   а браузер ломает.

3. **Перетаскивание набора.** Выделить рамкой можно, но потянув за узел,
   двигаешь только его: в коде один `dragId`. Самый заметный пробел свежей
   функции.

4. **Редактируемость по духу, а не по букве.** Критерий К7 считает долю узлов
   вне `absolute` — 96.9%. Но поведенческая проверка (утроить текст в абзаце)
   показала: на пяти сайтах из восьми страница **не перетекает**, потому что
   на контейнерах стоят фиксированные высоты, а `noWrap` — на 55–86%
   текстовых узлов. Мёртвая копия вернулась в другом обличье: не абсолютная, а
   пришпиленная пикселями. **Это противоречит смыслу редактора и важнее
   любого процента точности.**

### Среднесрочное

5. **Вертикальный дрейф.** На длинной ленте смещение накапливается до −1095px
   на 90% глубины при общей ошибке высоты 0.9%: нижний край сходится, а
   содержимое уехало. Критерий высоты этого не видит конструктивно.

6. **Измеритель текста.** Не ломает строку по дефисам и не знает метрик
   половины шрифтов. Влияет на MDN, на высоты лонгридов и на паритет холста с
   экспортом. В приложении текст меряет Pixi — там та же проблема.

7. **`wrapInset` не выражается в кодогене.** На холсте обтекание
   восстановлено, в экспортированном HTML — нет: простого CSS-эквивалента
   «укоротить только часть строк» не существует.

8. **Шкала не измеряет двух вещей**, которые видит глаз: перетекание при
   правке текста и вертикальный дрейф по глубине. Стоит добавить К9 и К10 —
   тогда следующие круги будут мерить то, что шкала сейчас пропускает.

### Долги инфраструктуры

9. **11 бинарных файлов не на GitHub** — мост передаёт содержимое как UTF-8.
   Иконки Tauri генерируются из `design/icon.svg` на `postinstall`, а четыре
   фотографии облегчённой фикстуры отсутствуют; от стендов они не требуются.

10. **104 снимка весом ~50 МБ не в репозитории.** Любой восстанавливается
    одной командой `live-snapshot.mjs`, но набор для регрессий пока живёт
    только локально.

11. **Rust проверяется только на машине пользователя.** В песочнице нет
    тулчейна: crates.io закрыт, сборка Tauri под Linux упирается в
    webkit2gtk. Из этого класса ошибок арбитр ловит только баланс блочных
    комментариев.

## 7. Как работать с проектом

```bash
git clone https://github.com/the-vanand/plexus.git
cd plexus
npm install          # зависимости + иконки из design/icon.svg
npm run tauri dev    # первая сборка Rust — несколько минут
```

Проверка перед правкой и после:

```bash
npm run check                                          # арбитр, 10 проверок
npx tsx tools/harness/bulk.ts                          # сводка по фикстурам
npx playwright-core install chromium                   # один раз
node tools/harness/live-snapshot.mjs <url> 1440 <имя>  # снять живой сайт
npx tsx tools/harness/snapshot-check.ts fixtures/snapshots/<имя>.json
```

**Правило для любых правок импорта:** прогонять по всем фикстурам, а не по
одной. Правка, чинящая Википедию и ломающая tauri.app, качества не повышает.

**Правило для приборов:** менять их можно только в сторону строгости и только
с обоснованием. Гейт, который никогда не падает, — декорация; каждый новый
стенд стоит проверять подложенной ловушкой.
