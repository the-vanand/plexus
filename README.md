# Plexus

**Визуальная full-stack IDE: холст, логика и база данных — в одной системе.**

Это каркас десктоп-приложения на Tauri 2: canvas-редактор с auto-layout моделью
(в духе Figma), генерация чистого HTML/CSS с якорями `data-plx-id`, файловый менеджер,
вкладки, инспектор свойств и встроенная консоль.

**Текущая версия: 0.11.0.** История изменений с обоснованиями и замерами —
в [CHANGELOG.md](CHANGELOG.md). Правило работы над проектом: искать корневую
причину в движке, а не латать симптом; проверять гипотезу на данных, прежде
чем править; честно называть ограничения.

## What's new in v0.8.0 (deep re-analysis of the reference site)

Each item below was traced to a root cause in the engine, not patched at the surface.

1. **Text still drifting → font-readiness race.** The solver measured text with the
   *system* font before the theme webfont finished loading, then the renderer drew with
   the loaded webfont — different metrics, shifted lines. Layout is now re-measured on
   both `fonts.loadingdone` **and** `fonts.ready`.
2. **Styling not fully copied.** The importer now carries over `letter-spacing`,
   `text-transform: uppercase`, `line-height`, `opacity`, `border` / `border-top`
   (section dividers) and the `font:` shorthand (`font: italic 38px var(--serif)`).
   All of them are editable in the inspector and emitted into CSS.
3. **Preview navigation loaded nothing.** Pages were served via `srcDoc`, whose origin is
   `null` — so `page.html` links and `#anchors` went nowhere. Preview now builds a **blob
   URL per page**: in-page anchors scroll natively, page links switch the blob, external
   links are reported instead of hijacking the frame.
4. **Footer wasn't separable/configurable.** The importer assigns semantic **roles**
   (`header` / `nav` / `section` / `footer`) — the footer becomes a named, selectable block,
   the role is editable in the inspector, and codegen emits real `<footer>` / `<header>` tags.
5. **Page window too small / didn't fit content.** A frame's fixed height acted as a hard
   cap and clipped content. Now it's a **minimum**: frames grow to fit, plus a
   "Fit to content" button in the inspector.
6. **Elements outside the page weren't clickable.** Hit-testing stopped at the frame
   bounds. Children are now tested even when the pointer is outside the parent — anything
   that overflows the page is still selectable.
7. **Animation import (new).** Scroll-reveal is imported: the classic
   `opacity: 0 + transform + transition` + `.visible` pattern is detected and converted into
   a **reveal animation** (fade / up / down / zoom, duration, delay) — editable in the
   inspector and compiled to CSS + IntersectionObserver, exactly like the source site.

## Что нового в v0.7.4 (паритет текста)

- **Текст измеряется тем же движком, что и рисуется.** Раньше решатель раскладки
  переносил строки своим алгоритмом (canvas 2d), а экран — алгоритмом Pixi; любое
  расхождение в округлении давало лишнюю строку и «поехавший» текст. Теперь
  решатель использует Pixi CanvasTextMetrics — перенос в раскладке и на экране
  совпадает по построению. Класс проблем «текст наезжает» устранён, а не залатан.
- Подписи кнопок переносятся ВНУТРИ кнопки (не выползают на соседей).
- Absolute-элементы зажаты и по вертикали (не ниже нижней кромки родителя).

## Что нового в v0.7.3 (починка раскладки импорта)

По скриншоту нашлись 3 бага в самом решателе:
- **Элементы уходили за рабочую область.** Двухколоночные секции с абзацами получали
  гигантскую «hug»-ширину (интринсик считался по нерасщеплённому тексту) и вылезали
  вправо. Теперь строка гарантированно не шире родителя: фикс-ширины ограничены, а при
  переполнении все колонки равномерно ужимаются. Плюс ширина любого ребёнка ≤ ширины
  родителя.
- **Фото растягивались.** Спрайт тянулся под прямоугольник. Теперь `object-fit: cover` —
  масштаб «заполнить» + центр-кроп маской.
- **Форма «терялась в пространстве».** Absolute-элементы не были ограничены рамкой —
  теперь прижимаются в пределы родителя.

Итог: импортированный COSPEX помещается в рамку страницы, фото не плющит, контактная
форма — внутри нижней секции.

## Что нового в v0.7.2 (починка шапки)

Диагностика по модели показала две настоящие причины, почему навбар «работал не так»:
- **@media-оверрайды текли в десктоп.** Мобильное правило `.site-header nav{flex-direction:column;display:none}`
  из `@media(max-width…)` применялось как обычное → навигация становилась вертикальной.
  Импортёр теперь **полностью выкидывает `@media/@keyframes/@supports`** и берёт десктоп-базу.
- **Скрытый гамбургер тащился в бар.** `.menu-toggle{display:none}` не учитывался → в шапке
  висела лишняя кнопка «Menu». Теперь элементы с `display:none` пропускаются.
- **Ширина детей ряда.** В горизонтальном контейнере дети по умолчанию `hug` (бренд слева,
  ссылки справа), а не делят ширину 50/50.

Итог: импортированная шапка COSPEX — горизонтальная полоса, слева «COSPEX», справа
в один ряд ссылки-якоря (#collections…), плавная прокрутка к секциям.

## Что нового в v0.7.1

- **Якорная навигация шапки (починка «шапка не работает»).** Причина: при импорте
  ссылки `href="#collections"` сохранялись, а у секций терялся `id` — якоря вели в
  никуда. Теперь: у узла есть **«Якорь (id)»** (инспектор), импорт сохраняет `id`
  секций, кодоген пишет `id=…`, а `html { scroll-behavior: smooth }` даёт плавный
  переход. Ссылки `#section` в шапке снова прокручивают к секциям.
- **Ссылка у текста/кнопки — поле в инспекторе** (в т.ч. `#section`, `page.html`, URL).
- **Навбар и подвал редактируются.** У авто-навбара/подвала — кнопка
  **«Разобрать для редактирования»**: превращает умный блок в обычные элементы
  (бренд + ряд текст-ссылок / ссылки + копирайт), которые правишь как хочешь.
- **Окно нового проекта — нативный выбор папки** (как в Проводнике Windows):
  кнопка «📁 Выбрать папку…» открывает системный диалог, путь виден, показывается
  куда ляжет проект. Путаный внутренний обзор убран.

## Что нового в v0.7

- **Инструменты «верхнего бара» (как у анализируемого сайта).** У любого контейнера/фрейма
  в инспекторе появилась секция **«Шапка»**: «Закрепить сверху (sticky)» + «Фон при
  прокрутке». Бар прилипает к верху (`position: sticky`), а при скролле «затвердевает»
  выбранным фоном с `backdrop-filter: blur` — ровно поведение `.site-header.scrolled`
  из COSPEX. В коде это чистый CSS + маленький scroll-листенер в script.js (и в Next).
  На холсте sticky-узел помечен бейджем 📌. Импорт теперь распознаёт `position:fixed/sticky`
  и подтягивает фон из правил `.scrolled/.sticky` (включая rgba и составные селекторы).
- **Импорт сайта по ссылке** («Файл → Импорт сайта по ссылке…»): вводишь URL — Plexus
  скачивает HTML и связанные CSS (HTTP-запрос идёт из Rust, обходя CORS webview),
  разбирает вёрстку в страницу, картинки подтягивает по абсолютным URL. Динамические
  (JS-рендер) сайты импортируются частично.

## Что нового в v0.6

- **Импорт HTML-сайта** («Файл → Импорт HTML-сайта…»): выбираешь index.html —
  Plexus разбирает вёрстку и локальный CSS (переменные, классовые стили) и строит
  страницу на холсте: секции → контейнеры с направлением из display:flex,
  заголовки/абзацы → тексты с размерами и цветами, картинки → image-узлы
  (локальные копируются в site/assets), ссылки-кнопки → кнопки с href,
  поля форм → inputs. Дальше это обычные узлы Plexus: токены, провода, экспорт.
  Ограничения v1: absolute-оверлеи складываются в поток, каскад CSS упрощён,
  чекбоксы пропускаются.

## Быстрый старт

Требования:

- **Node.js 20+** — https://nodejs.org
- **Rust (stable)** — https://rustup.rs
- **Windows:** Visual Studio Build Tools с нагрузкой «Разработка на C++»
  (без линкера MSVC Rust на Windows не собирается) и WebView2 Runtime —
  на Windows 11 он уже есть
- **Linux:** системные зависимости Tauri 2 — https://tauri.app/start/prerequisites/

```bash
git clone https://github.com/the-vanand/plexus.git
cd plexus
npm install          # зависимости фронтенда + иконки приложения
npm run tauri dev    # десктоп-приложение; первая сборка Rust — несколько минут
```

Три команды, без ручных шагов. Иконки приложения **генерируются** из
`design/icon.svg` на `postinstall`, а не хранятся в репозитории: источник
один, рассинхронизировать его с бинарными копиями невозможно, и история не
пухнет от PNG и ICNS. После правки SVG:

```bash
npm run icons -- --force
```

Только веб-превью, без Rust (файловые диалоги и снимок страницы через скрытое
окно будут недоступны — код это знает и деградирует явно):

```bash
npm run dev          # http://localhost:5173
```

Проверить, что окружение исправно, до всякого запуска:

```bash
npm run check        # восемь проверок: типы, сборка, пять стендов
```

**Чего в репозитории намеренно нет.** Четырёх фотографий в
`fixtures/cospex-lite/assets/` — от стендов они не требуются (проверки считают
теги `<img>`, а не открывают файлы), нужны только чтобы фикстура отображалась
с картинками. Полноразмерные материалы заказчика в `fixtures/cospex-site/`
исключены через `.gitignore` осознанно: 2.5 МБ бинарных данных, которые
воспроизводятся облегчённой копией.

## Стенды проверки

Правки движка нельзя проверять глазами: раскладка ломается тихо. Поэтому в
`tools/harness/` живут прогоны, которые меряют результат числами. Все цифры в
CHANGELOG получены ими, а не на глаз.

```bash
# импорт HTML: ширина страницы, переполнения, шрифты, сетки, картинки
npx tsx tools/harness/report.ts fixtures/cospex-lite/index.html 1440

# точечная сверка отдельных узлов с оригиналом
npx tsx tools/harness/probe.ts "hero-shade" "Where Football"

# полный круг: HTML -> сцена -> кодоген -> HTML (результат в out/)
FIXTURE=fixtures/cospex-lite/index.html npx tsx tools/harness/roundtrip.ts 1440 --inline

# каталог: все 28 блоков и 23 элемента через решатель и кодоген
npx tsx tools/harness/catalog.ts

# демо-страница из 16 блоков (результат в out/demo/)
npx tsx tools/harness/demo-page.ts

# диагностика источника: статика / гидратация / каркас SPA
npx tsx tools/harness/source-check.ts fixtures/cospex-lite/index.html

# импорт по снимку: сверка расчёта с ИЗМЕРЕННОЙ браузером геометрией
npx tsx tools/harness/snapshot-check.ts fixtures/snapshots/cospex-1920.json
```

Стенды считают текст детерминированной заглушкой (`measure-stub.ts`): в Node нет
canvas, поэтому Pixi `CanvasTextMetrics` недоступен. Алгоритм переноса тот же,
поэтому структурные ошибки ловятся честно, а пиксельная сверка — уже в самом
приложении.

Фикстуры: `fixtures/cospex-lite` — облегчённая копия реального сайта для
регрессий, `fixtures/snapshots/cospex-1920.json` — снимок, снятый настоящим
Chromium (231 элемент). Полноразмерные фото заказчика в репозиторий не
попадают — см. `.gitignore`.

## Структура

```
plexus/
├── src/                  # фронтенд (React + TypeScript)
│   ├── core/             # ЯДРО — без единого импорта из Pixi/React
│   │   ├── types.ts      #   модель документа: SceneNode, auto-layout свойства
│   │   ├── scene.ts      #   операции над scene graph + hit-test + стартовый документ
│   │   ├── layout.ts     #   решатель auto-layout (hug / fill / fixed, gap, padding…)
│   │   ├── codegen.ts    #   scene graph → чистый HTML/CSS (+ якоря data-plx-id)
│   │   └── store.ts      #   состояние (zustand) + undo/redo + вкладки + логи
│   ├── canvas/           # РЕНДЕРЕР — заменяемый слой (сегодня PixiJS/WebGL, завтра Rust/wgpu)
│   │   ├── renderer.ts   #   отрисовка scene graph
│   │   ├── interactions.ts#  пан/зум/выделение/перетаскивание/контекст-меню
│   │   ├── guides.ts     #   умные направляющие и снап (как в PowerPoint/Figma)
│   │   └── measure.ts    #   измерение текста (canvas 2d)
│   ├── components/       # IDE-оболочка: панели, вкладки, инспектор, консоль
│   └── tauri/api.ts      # мост к Rust-командам с браузерными фоллбэками
├── src-tauri/            # Rust: окно, файловая система, запуск команд
└── design/               # иконка и брендинг
```

## Архитектурные принципы (важно для контрибьюторов)

1. **Ядро не знает о рендерере.** `src/core/` не импортирует ни Pixi, ни React.
   Рендерер потребляет модель через тонкий интерфейс — это позволит заменить
   PixiJS на Rust + wgpu без переписывания редактора.
2. **Auto-layout, а не абсолютные пиксели.** Модель раскладки (direction / gap /
   padding / hug / fill / fixed) отображается в flexbox почти 1:1 — поэтому
   генерируемый код чистый и адаптивный. Absolute — осознанный escape hatch.
3. **Каждый узел оставляет якорь в коде.** Генератор пишет `data-plx-id` в HTML.
   Эти якоря — фундамент будущей двусторонней синхронизации код ⇄ холст и
   маппинга ошибок на элементы.
4. **Кодоген детерминирован.** Одна модель → байт-в-байт один и тот же код.
